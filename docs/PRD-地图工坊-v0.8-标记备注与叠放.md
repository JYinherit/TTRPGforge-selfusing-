# PRD：地图工坊 v0.8 —— 「一格上的东西，说得清、点得到」

- 产品：ClueForge 离线 KP 工具箱 · 地图工坊
- 版本：v0.8（承接 v0.7：批量选择/标记/地板材质）
- 立项日：2026-10-29 ｜ 回看日：2026-11-12
- 文档性质：范围裁决 + 用户故事 + 验收标准。**不含实现代码。**
- 一句话结论：**四个候选里只做「标记备注 + 同格叠放」，另外三个进不做清单并附复审条件。**

## 0. 决策摘要

| 候选 | 证据等级 | 赌注 | 裁决 | 一句话理由 |
| --- | --- | --- | --- | --- |
| 标记备注与叠放 | B（结构证据：字段已埋、UI 未做） | 小 · 可逆 | **做（v0.8）** | 补的是上一轮已经挖好、没填的坑；零 schema 风险；直接服务"线索"这个产品定位 |
| 素材库 | C（直觉/竞品，无行为证据） | 中 · 跨图资产池要动存储层 | **先验证（不写）** | 同图复用已被 hash 去重覆盖，真价值只剩跨图；先花 0 产能把数拉出来 |
| 多楼层 | C（竞品 + 埋了半截 `level` 字段） | **大 · 动数据模型** | **不做（本迭代）** | 需要 MapDoc v2，牵动导出/存档/生成器；先用手工笨办法跑一次真实团去证伪 |
| 光照 / 视野墙 | D（纯竞品驱动） | 大 · 开始做平台 | **不做** | 产物是 PNG/JSON 交给桌上的人，**没有消费方**；做了也只有 GM 自己看 |

> 备注与叠放不是两个需求，是一个需求的表里：备注写了，同格多标记时被上层遮住，写了也看不见、点不到 —— 所以叠放是备注的**渲染前提**，必须同批交付。

## 2. 需求裁决卡

### 卡 A：标记备注与同格叠放

```
# 需求：标记备注与叠放｜来源：☑ 用户（KP 本人） ☑ 数据发现（字段已埋未用）
四问：
1. 哪个用户：单人 KP（本工具唯一使用者），在备团/临场主持调查类场景时。
2. 什么场景下发生：把"这里有什么"写到地图上——柜子里有备用钥匙、尸体的口袋有信、
   这个红 token 是"失踪的管家"。格子只装得下一个字形，装不下一句话。
3. 现在用什么笨办法：① 房间名塞信息（"储藏室（钥匙在罐子里）"）② 字形硬编码 A/B/1/2
   ③ 另开记事本对照坐标 ④ 干脆不标，靠记性。
4. 痛到愿意换吗：证据等级 B。结构证据是上一轮已把 label 字段和 40 字校验埋进模型，
   说明当时已预判；但"预留字段"不是行为证据，本迭代要靠判定线自证（见 §5）。
假设：若一格上的标记能写下 ≤40 字备注，且同格多标记能被展开查看/选中，
      则 KP 会用它替代"房间名塞信息 + 另开笔记"。验证看导出 JSON 的 label 填写率
      与"房间名长度中位数"这个反向指标。
赌注大小：☑ 小（可逆；新增可选字段，最坏情况是没人用，删掉 UI 即可，存档无损）
机会成本：批准它 = 把「多楼层 schema v2 设计」与「跨图素材库」各推迟一个迭代。
          代价目前≈0：多楼层缺"笨办法验证"、素材库缺"重复上传次数"这个数，两条证据都还没到手。
裁决：☑ 做（v0.8）｜复审条件：见 §5 判定线不达标条款
```

```
四问：
1. 哪个用户：单人 KP。
2. 什么场景：新开一张地图，想复用上一张里已经传过的 NPC 立绘 / 物件图。

```

### 卡 C：多楼层

```
# 需求：多楼层（同一地图多张楼层平面）｜来源：☑ 竞品 ☑ 用户（顺手提到）
四问：
1. 哪个用户：跑多层地牢 / 多层建筑的 KP。

  这会让任何人（包括我）以为"只差一个楼层下拉框"。实际差的是一座桥：
  楼层切换 → 每层独立 size/background → 按层导出 PNG → 自动存档多文档 →
  JSON v2 与 v1 双向兼容 → 生成器按层出图。这是**改变产品数据模型**的大赌注。

裁决：☑ 不做（本迭代）｜复审条件：出现"同一套改动要在 ≥3 张地图上重复维护"
      或"计划里出现 ≥3 层结构一致的地牢"。
前置要求（必须先做，不许跳过）：用最丑的原型验证需求形态 ——
  手工存 3 份 JSON + 一张手画的对齐参考图，跑一次真实团。
  若结论是"其实我只需要一次性按层出三张 PNG"，那答案不是多楼层，
  而是「批量导出多张图」—— 便宜一个数量级。
```

## 3. v0.8 范围与用户故事

**唯一假设（本迭代只押这一条）**：
一格上的信息能被写下、被看见、被点中 —— 因此 KP 会把"这里有什么"从房间名和记事本搬回地图上。

**范围**：US-4（存档不破）→ US-1（写备注）→ US-2（按需看见）→ US-3（同格叠放）。
**排期顺序即优先级**：写成两半交，先交"写得进去"，再交"看得见"。

### US-1 写备注（P0）
> 作为 KP，我要给一个标记写 ≤40 字备注，这样我不用另开笔记就知道这个 token 是谁、这里有什么。

验收标准：
- **AC1.1** 选中标记时，检查器出现「备注」单行输入框，预填当前 label；空值时占位符为 `如：抽屉里有备用钥匙`。
- **AC1.2** 失焦或回车即写回文档；`Ctrl+Z` 一步可回退；一次连续输入只产生 ≤1 条历史（按次/防抖，不许一字一条）。
- **AC1.3** 长度上限 **40 个字形**（按 `Array.from` 计，不按 UTF-16 code unit），与 `serialize.ts:250` 口径统一；达到上限显示 `40/40` 并停止接收输入，**不做静默截断**（静默截断会造成"存得下、显示不了"的分叉）。
- **AC1.4** 输入框强制单行：粘贴含换行内容时换行折叠为空格，不允许破坏画布与检查器布局。
- **AC1.5** 只输入空白字符 → 归一化为"无备注"（不得用 40 个空格占位）。
- **AC1.6** 导出 JSON 后重新导入，label 原样保留；无备注的标记不得写出空 `label` 键（避免全量存档膨胀与差异噪音）。
- **AC1.7** 打开 v0.7 及更早的存档：不报错、不弹迁移提示、不改变 `version`。

### US-2 按需看见备注（P0）
> 作为 KP，我要在画布上一键看到所有备注，这样出图前能检查信息是否齐全。

验收标准：
- **AC2.1** 视图区新增「显示备注」开关，**默认关**；与「显示格线」同级同款，属视图态。
- **AC2.2** 开关状态**不写入存档**（不进 `MapDoc`），重开工程回到默认关。
- **AC2.3** 开启后，有备注的标记旁显示浮签：≤12 个字形截断 + 省略号，字号 10，半透明底，不遮挡标记字形。
- **AC2.4** 浮签不参与选中/拖动/框选（点击穿透到标记本体），且不进入导出。
- **AC2.5** 缩放到 <50% 时浮签自动隐藏（避免糊成一片）；缩放回 ≥50% 自动恢复。
- **AC2.6** 标记数达到上限 500 且浮签全开时，拖动仍可交互，不出现秒级卡顿。
- **AC2.7** 「导出 PNG」默认**不含**浮签；提供「导出含备注」勾选项（默认关）。
  —— 默认关是刚性要求：备注写的是 KP 的秘密（"这里有陷阱"），印到玩家手上的图里就泄底。

### US-3 同格叠放（P1）
> 作为 KP，我要在一格里放多个东西并且随时点得到、看得清，这样桌面不会迫使我为了看见而把标记挪开。

验收标准：
- **AC3.1** 同一格出现 ≥2 个标记时，该格显示叠放角标（如 `②`），位于标记右上，不遮挡字形与浮签。
- **AC3.2** 点击角标（或双击该格）打开浮层，列出该格全部标记：色点 + 字形 + 备注首 20 字；点列表项选中对应标记并关闭浮层。
- **AC3.3** 浮层内可「上移一层 / 下移一层」，渲染顺序随之变化并写回文档；`Ctrl+Z` 一步可回退，一次调整只产生一条历史。
- **AC3.4** 同格判定用**中心格**归属（按 `grid.cell` 折算文档坐标，不用屏幕坐标）：4 格标记只归属中心所在那一格，绝不允许同一标记被两格各算一次。
- **AC3.5** 与既有批量语义共存：框选跨多格的叠放组批量移动后，角标归属随中心格更新；「删除这 N 个」后角标数字同步更新，不允许出现"角标 3 但只剩 1 个标记"的脏视图。
- **AC3.6** 叠放角标与浮层**不进入 PNG 导出**，且不提供开关 —— 出图必须干净，编辑态 UI 不许漏到产物里。
- **AC3.7** 缩放/平移后角标归属与浮层内容不变（文档坐标为唯一真相）。

### US-4 存档不破（P0，技术性但对 CPO 是硬约束）
> 作为已经攒了十几个战役工程的使用者，我要这次升级不动我的旧存档，这样我不用在"新功能"和"我的数据"之间选。

验收标准：
- **AC4.1** `MapDoc.version` 保持 `1`；新增字段全部可选（`label` 已有，叠放新增 `z?: number`），旧存档不迁移、不升版本号。
- **AC4.2** 未知/扩展字段继续透传（沿用 `serialize.ts:176-187` 的 `...g` 展开语义），不得因新功能丢失 `tags/level/notes`。
- **AC4.3** 导入校验容错而非拒绝：label 超 40 字形 → 截断并保留整份文件；`z` 非有限数或重复 → 归一化为插入序，**不因为一个字段坏掉就拒收整张图**。
- **AC4.4** 撤销/重做、自动存档、PNG 导出、JSON 导入导出四条既有链路全部回归通过（本次改动的验收包含"没弄坏旧的"）。

### 边界清单（必须在上线前逐条过）
1. 4 格标记覆盖 4 格、但只算 1 格 → 与"看起来重叠"的观感落差，接受，并写进已知限制。
2. 角标 / 浮签 / 房间名标签三者同时出现在一格时的层级：房间标签在下，角标在中，浮签在上。
3. 空白备注、纯 emoji 备注、全角空格备注的归一化。
4. 叠放组内标记被删到只剩 1 个 → 角标必须消失。
5. 同一文档里 label 与 z 的 500 条上限下的渲染开销。
6. 导出 PNG 2x 时不含角标/浮签（因 AC3.6/AC2.7 已排除，这条是回归检查项）。

## 4. 优先级与机会成本

| 优先级 | 内容 | 估时（估，非实测） | 批准它 = 推迟什么 | 为什么这个顺序 |
| --- | --- | --- | --- | --- |
| P0 | US-4 存档不破 + US-1 写备注 | 0.5 天 | 浮签与叠放各推后半天 | "写得进去"是主价值；写不进去时，看得见也没内容可看 |
| P0 | US-2 按需看见（浮签） | 0.5 天 | 叠放推后半天 | 写了看不见 = 价值只兑现一半；但浮签是放大器，不是地基 |
| P1 | US-3 同格叠放 | 1 天 | 素材库评估、多楼层原型 | 没有它，备注在遮挡场景下白写；但它可以晚一版 |
| — | 回归（PNG / JSON / 撤销 / 自动存档） | 0.5 天 | 任何新功能 | 不回归的交付是负资产 |
| 切一刀 | 若只有 1 天产能 | — | 只交 US-4 + US-1 | 我宁可要"能写备注的 v0.8.0"，也不要"半截叠放的 v0.8" |

**总产能**：≈1.5–2 个开发日（自用项目，按周末口径）。
**明说的机会成本**：这 2 天不从别的项目抢，就从「多楼层原型」和「素材库验证」抢 —— 而这两件本来也还没到"该动手"的时候（一个没跑笨办法验证，一个没拉出重传次数）。所以这次的机会成本接近零，这是选它的**主要**理由，不是附带理由。

## 7. 需要拍板的口径（已拍，附理由）

1. **备注是否进 PNG 出图** → 默认不进。备注是 KP 的秘密，出图是给玩家看的；给开关，但默认关，且默认值不记忆。
2. **同格口径** → 中心格归属，不用覆盖格。判定成本低、可解释；代价是 4 格标记"看起来压着"但不算同格，接受并写进已知限制。
3. **40 字上限** → 沿用 `serialize.ts:250` 的 40，但把计数口径从 code unit 统一为字形（`Array.from`），因为 UI 若按 code unit 收，emoji 会被存档偷偷切半。
4. **叠放的数据表达** → 标记上加可选 `z?: number`，不引入独立图层系统。图层系统是"素材库/多楼层"那个量级的活，别偷跑。
